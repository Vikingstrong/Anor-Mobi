# Architectural Decision Records

Дата исходных решений: 2026-11-10. «Принято для плана» не означает реализовано или проверено на телефоне.

## ADR-001 — Локальное личное приложение

Принято для плана. Основной пользователь — автор, возможно несколько друзей. Каждый APK работает со своей SIM и своим cache. Backend, авторизация и синхронизация не нужны. Альтернатива — серверный продукт с аккаунтами — не решает текущую задачу и повышает стоимость/риски. Будущая установка другу не является основанием для multi-user backend.

## ADR-002 — React Native + Expo Development Build + Kotlin

Принято для плана. Пользователь знаком с React/TS; native нужен для Android telephony. Expo Modules API даёт локальный Kotlin-модуль без публикации npm-пакета. Prebuild генерирует native project из config; важный код в modules/plugin. Альтернативы: Expo Go не включает наш код; bare RN даёт больше ручного обслуживания; чистый Kotlin меняет учебную цель. Версии зафиксировать на этапе инициализации после совместимости. Основание: [Expo custom native code](https://docs.expo.dev/workflow/customizing/).

## ADR-003 — Разделить баланс и пакеты

Принято. Пользователь подтвердил USSD для денежного баланса и отдельное SMS для пакетов. Отправляем только известный `*100#`; callback и SMS не считаются одной атомарной операцией. Refresh All не отправляет повторную команду ради пакетов. Альтернатива — единый «всё обновлено» — скрывает устаревшие поля. Программная работа USSD остаётся неподтверждённой.

## ADR-004 — Ручной SMS import в MVP

Принято. Вставка → preview → commit, без SMS permissions. Есть один реальный образец ULTRA; parser ограничить подтверждённым форматом. READ_SMS/RECEIVE_SMS и notification listener отложены: Android/installer/Play ограничения и широкие права не оправданы MVP. Альтернатива — automation сразу — не гарантирует работоспособность даже при sideload. Основания: [Android permissions](https://developer.android.com/reference/android/Manifest.permission#RECEIVE_SMS), [Play policy](https://support.google.com/googleplay/android-developer/answer/10208820).

## ADR-005 — Разделить тариф и наблюдения

Принято. ULTRA/LITE — отдельные определения; остатки, expiry, источник/время — самостоятельные наблюдения. Unknown отличается от 0. Выбор тарифа ручной, operator-reported label хранится отдельно. Не заменять пакеты полными лимитами после выбора тарифа. Официальные МБ сохранять без неявного 1024-пересчёта. Альтернатива — один объект «тариф с остатками» — смешивает catalogue и измерение.

## ADR-006 — Небольшой UI и store

Принято для плана: Zustand, AsyncStorage и StyleSheet. Альтернативы: Redux, SQLite, NativeWind и UI kits пока добавляют инструменты без нужной пользы. Typed storage adapter позволяет позже сменить реализацию. AsyncStorage без прикладного шифрования — осознанный компромисс для ограниченных данных, backup исключается. Два основных экрана не требуют тяжёлой навигации; пересмотреть при росте flow.

## ADR-007 — Явная SIM и единичная USSD-операция

Принято для плана. Целевой телефон A12/Android 12, Anor в SIM 2. Используем subscriptionId, повторно валидируем активность и contextId. Один pending request, timeout с exactly-once completion, без automatic retry. Нет гарантии отмены modem session. Альтернатива — default SIM/параллельные запросы — риск неправильного счёта и конфликтов. После смены SIM данные текущего контекста сбрасываются. Полную автоматическую идентификацию заменённой SIM без чувствительных ID не обещаем.

## ADR-008 — Локальная сборка без обязательной Studio

Принято по обсуждению с владельцем. React Native разрабатывается в редакторе; локальной сборке нужны JDK + SDK Command-line Tools/Platform Tools/Platform/Build Tools и Gradle wrapper. Эмулятор не нужен, USSD проверяется реальным телефоном. Android Studio на Windows можно оставить, но она не готовит текущую Linux-среду автоматически. Альтернатива EAS Cloud возможна позже; не обязательна. Большие установки и зависимости на этапе документации не выполняются.

## ADR-009 — Сначала документация, затем реализация по разрешению

Принято по исходному заданию. Сейчас создаются только документы; не инициализировать приложение, не устанавливать toolchain, не делать native spike и не публиковать APK. Следующее разрешение владельца открывает соответствующий объём реализации. GitHub будет подключён владельцем; не исправлять служебный `.git` среды. Работать короткими проверяемыми шагами с объяснениями Kotlin и parser logic.

## Открытые решения

- Точная модель/One UI и совместимые SDK/toolchain версии.
- Надёжность USSD callback и фактический timeout на A12/Anor.
- Sender/время/варианты SMS, формат LITE, семантика основного интернет-поля.
- Timezone expiry, конверсия официальных МБ в отображаемые ГБ.
- Способ распространения за пределами личного APK, если появится потребность.

Изменения добавлять новым ADR или отметкой superseded с причиной; не стирать историю принятых ограничений.

## ADR-010 — Начало реализации и лёгкий стартовый экран

2026-11-10: владелец разрешил реализацию. Первая итерация ограничена официальным blank TypeScript шаблоном Expo SDK 58, совместимыми React Native/React и development build. Не добавляем Zustand, AsyncStorage и Jest, пока нет соответствующей логики; Safe Area dependency нужна для системных отступов Android. `expo-dev-client` нужен для будущего Kotlin-модуля. Стандартные UI-компоненты/StyleSheet без blur и анимаций отвечают уточнению владельца о минимализме и Helio P35. Запуск и производительность на телефоне ещё не проверены. [Таблица совместимости Expo](https://docs.expo.dev/versions/latest/).

## ADR-011 — Ограниченная локальная сборка после зависания ноутбука

2026-11-10: владелец сообщил о заполнении RAM, высокой CPU-нагрузке и принудительном выключении. После reboot Gradle/Kotlin не обнаружены; RAM 16 GiB, MemAvailable около 6.8 GiB, swap/zram 8 GiB. Лог не подтвердил точную причину OOM. Первый APK не завершён. Вместо повторного запуска добавлен Linux/systemd build wrapper: суммарный cgroup MemoryHigh 3 GiB, MemoryMax 4 GiB, CPUQuota 150%, nice 10. Gradle: один worker, parallel=false, heap 1536 MiB, Kotlin in-process. Настройки сохраняются Expo config plugin, не ручной правкой android/. Metro — один worker. Ограничения проверяются без компиляции; реальная сборка будет отдельным действием после восстановления. Альтернатива — облачный build, если лимита недостаточно; автоматической отправки исходников нет. [Gradle](https://docs.gradle.org/current/userguide/performance.html), [Kotlin execution strategy](https://kotlinlang.org/docs/gradle-compilation-and-caches.html#defining-kotlin-compiler-execution-strategy).

## ADR-012 — Системная тема, индикаторы пакетов и честный manual preview

2026-11-11: после просмотра владелец запросил тёмную тему, default system, числа + заполненные полосы, максимум справа мелким шрифтом и время под каждым пакетом. Добавлены две палитры/Appearance, PackageCard и отдельно помеченные синтетические preview-данные без сохранения. Новых зависимостей и новой native-сборки нет. Текущий установленный APK следует теме через публичный runtime API, будущий native config — automatic. Выбор темы пока в памяти.

Нельзя отображать «ответ получен» или менять время остатков после открытия *100# в чужом dialer. Пока native bridge отсутствует, кнопка называется «Открыть *100#» и объясняет ручную проверку. Подтверждён sender AnorINFO и многоминутная задержка SMS; будущие состояния USSD и SMS раздельны. Основная техническая следующая задача — настоящий native USSD callback, не имитация обновлений.

## ADR-013 — Раздельные команды и настоящий native-поток

2026-11-11 владелец уточнил: *100# даёт только баланс; *104# запрашивает тариф/остатки с отложенным SMS AnorINFO. Это заменяет прежнее предположение о пакетах после *100#. Kotlin allowlist содержит ровно эти две команды; refresh не открывает dialer. При общем обновлении выполняются последовательно 100 и 104; после transport error/тайм-аута первого запрос второго автоматически не запускается. Повторный 104 при ожидании SMS блокируется; баланс можно проверить отдельно.

Подготовлены AnorTelephony (USSD + foreground receiver), AccountController, парсеры и manual preview/commit SMS. Автоприём opt-in через RECEIVE_SMS, без READ_SMS; только пока приложение открыто. Неопределённая/другая подписка не обновляет текущий счёт. Background/killed-process delivery не обещается. При недоступном разрешении остаётся ручной импорт.

Для Android-only снимка выбран небольшой отдельный Expo storage module: AtomicFile в noBackupFilesDir. Это заменяет запланированный AsyncStorage, уменьшает runtime-зависимости и исключает пользовательский cache из backup. Сохраняются только типизированные значения/метаданные, не SMS-текст. Последовательная запись реализована storage adapter; React useSyncExternalStore соединяет UI с контроллером, Zustand пока не нужен.

Добавлены только dev-зависимости Jest 30/Babel для чистых тестов, без UI/native mock framework. TypeScript и 36 Jest tests прошли до нового поручения «без проверок собирай APK»; дополнительные тесты не запускались. Native работоспособность ещё должна быть подтверждена новой сборкой и A12.

## ADR-014 — CPU по уточнению владельца

Владелец сообщил о 12 ядрах/16 потоках и разрешил увеличить CPU. Текущий и будущий build scope получили CPUQuota=800%, MemoryHigh/Max остались 3/4 GiB. Число Gradle workers и Java heap не увеличены; это разрешённый потолок CPU, не обещание одновременного использования восьми потоков каждым компилятором. Wrapper останавливает наш Metro scope перед сборкой.

## ADR-015 — Anor Mobi, автономный APK и согласованные удобства

2026-11-11: владелец расширил итерацию: выполнить все согласованные функции перед следующей сборкой. Название Anor Mobi; package/scheme оставлены прежними, чтобы обновление сохранило данные. Собственный простой векторный знак, синий/голубой/жёлтый акценты по [официальному сайту Anor](https://anor.mobi/) (цвета inline CSS просмотрены 2026-11-11); приложение остаётся неофициальным. Статусы расположены у соответствующих кнопок; PNG-иконки вместо символов шрифта. Предупреждение <=10% применяется только к интернету.

Тема хранится отдельно в SharedPreferences через storage adapter, по умолчанию system. Ошибки сохранения показаны в настройках. Снимок schemaVersion=2 добавляет последние 30 структурированных ответов, с миграцией v1 без истории; лимит файла 128 KiB. История очищается отдельно от текущих остатков. Относительное время обновляет один таймер раз в минуту только в foreground.

Manifest SMS receiver с системным BROADCAST_SMS guard принимает только AnorINFO выбранной SIM после opt-in RECEIVE_SMS. Короткая работа выполняется через goAsync на последовательном IO executor, без сервиса, уведомлений, wake lock и автоматических USSD. Native извлекает только известные поля и пишет очередь (до 30 событий) в AtomicFile/noBackupFilesDir, не исходные SMS. JS при открытии повторно проверяет поля тем же чистым parser, обновляет снимок/историю, подтверждает очередь только после успешной записи. Timestamp предотвращает повторное применение; ошибка записи сохраняет очередь для повтора. Foreground event остаётся быстрым путём, raw body существует только в памяти. Force stop через настройки Android блокирует broadcasts до ручного запуска; реальное фоновое получение на A12 ещё требует ручного подтверждения.

Автономная частная preview-сборка запускается `npm run build:android -- --standalone`: assembleRelease с встроенным JS, без Metro. Пока сохранён существующий development signing key для обновления без потери данных; это не production/store signing. Minify/shrink отключены, лимиты памяти сохранены. Публикация и новая release signing identity не выполняются.

## ADR-016 — Расход и прогноз по наблюдаемым остаткам

2026-11-11: владелец поручил реализовать расход и прогноз. Новых permissions, зависимостей, фоновых USSD и сетевого обмена нет. Чистый domain/internetUsage вычисляет разницу показаний отдельно для основного/ночного интернета; UI показывает один компактный блок с переключателем, без графиков и новых таймеров.

Для достоверной границы пакета снимок v3 добавляет context к каждой записи истории: expiresLocal/tariffId/tariffName. v1/v2 мигрируют без потери значений/истории, но старый неизвестный context=null не используется в расчёте. Балансовые записи и перенесённые поля частичных SMS не являются новыми замерами. Смена контекста, рост остатка и конфликт одного timestamp разрывают последовательность. Равные показания в разное время — наблюдаемый нулевой расход; отсутствие наблюдений не равно нулю.

Окна — последние 24 часа и 7 дней, только целые интервалы проверок текущего пакета внутри окна. Не распределяем расход через границу окна по вымышленной равномерной интерполяции. Показываем фактические начало/конец и длительность наблюдений: это оценка между проверками, а не показание Android или точный суточный биллинг.

Прогноз: минимум 3 замера за >=24 часа в последних 7 днях; последний моложе 24 часов; известный неистёкший срок пакета. Средняя скорость = падение остатка / длительность; прогноз от последнего замера, включая время до открытия экрана. Операторское local expiry интерпретируется в зоне проекта Asia/Dushanbe (+05:00), независимо от timezone телефона; это принятое допущение продукта. При прежнем темпе показываем ожидаемый остаток к сроку или приблизительную дату исчерпания. Нулевой фактический остаток выделен отдельно, деления на ноль нет. Изменение расхода, невидимое пополнение между двумя проверками и задержка SMS могут менять прогноз — точность не обещаем. История ограничена 30 последними ответами, очистка удаляет и базу расчёта.

Версия метаданных приложения 0.3.0/code 3. TypeScript и 60 Jest tests прошли на готовой логике; новый APK/проверка на A12 отмечаются отдельно после разрешённой сборки. Постоянная подпись не меняется.

## ADR-017 — Коррекции МБ и автоматический выбор SIM

2026-11-12: владелец сообщил, что оператор иногда увеличивает остаток ошибочно, и поручил убрать сброс расхода/прогноза на таком росте. Это заменяет правило ADR-016 о новом baseline при любом увеличении. Внутри неизменного контекста пакета аналитика использует running minimum для расхода: рост не уменьшает накопленный расход, последующий возврат до прежнего минимума не считается повторно. Дальнейшее падение ниже минимума добавляет расход. Пример 1000→800→1200→800→700 = 300 МБ. Реальные показания/время/история не подменяются; прогноз использует фактический последний остаток и сохранённый средний расход. Новые срок/тариф по-прежнему разрывают расчёт. История восстанавливается по уже сохранённым записям, вручную очищать её не нужно. Ограничение: реальное пополнение без изменения контекста нельзя отличить от ошибки оператора; до нового минимума расход оценивается консервативно. Окна 24ч/7д и лимит истории 30 ответов прежние.

Автовыбор SIM — новое прямое поручение владельца: по carrierName/SPN находим Anor/Анор как отдельное имя, иначе системная default voice SIM, либо единственная активная SIM. Если обе SIM Anor — сначала default voice, затем ранее выбранная, затем стабильный порядок слотов. При двух SIM без Anor и без системной default voice не угадываем слот: объясняем необходимость ручного выбора. User-editable displayName — fallback только при отсутствии обоих операторских имён, для совместимости со старым APK. Не вводим выдуманные MCC/MNC/списки оператора.

Публичные Android API: [SubscriptionInfo.getCarrierName/getDisplayName](https://developer.android.com/reference/android/telephony/SubscriptionInfo), [TelephonyManager.getSimOperatorName](https://developer.android.com/reference/android/telephony/TelephonyManager#getSimOperatorName()), [SubscriptionManager.getDefaultVoiceSubscriptionId](https://developer.android.com/reference/android/telephony/SubscriptionManager#getDefaultVoiceSubscriptionId()). Проверено по документации 2026-11-12. Данные доступны не на каждой SIM/прошивке; реальное распознавание на A12 должно быть подтверждено новым APK.

Account v4 сохраняет simSelection:auto|manual; v1–v3 мигрируют в auto, сохраняя effective subscriptionId, историю и показания. Ручной выбор доступен и имеет приоритет до включения auto. Детекция выполняется по действию «проверить»/поиска SIM, не при запуске. Сначала READ_PHONE_STATE/CALL_PHONE по действию пользователя, затем native список/метаданные, чистый selector в JS и USSD для конкретной subscription. Фоновый receiver синхронизируется до запроса; при реальной смене SIM прежние readings/history не смешиваются с другой SIM. Переключение режима на той же SIM ничего не очищает. Нет новых permissions/зависимостей/авто-USSD.

0.3.1/code 4: TypeScript и 85 Jest tests прошли. Native изменения подготовлены, сборка и проверка на A12 ещё не выполнены; APK 0.3.0 не выдаётся за новую версию.

## ADR-018 — Акцентный цвет и выпуск 0.3.2

2026-11-12: владелец остановил сборку 0.3.1, затем поручил добавить выбор цветов и шестерёнку настроек, после чего явно разрешил сборку/установку и копирование APK в Download телефона. Версия результата 0.3.2/code 5 включает ADR-017. Анимации обсуждались как идеи и в эту итерацию не входят.

Семь accent presets: blue (прежний default), green, orange, red, purple, teal, pink. getPalette объединяет нейтральную базу light/dark и соответствующие оттенки акцента/подложки/полос. Цвета адаптированы для обоих режимов; системный режим и предупреждения сохраняют свои значения. Логотип/launcher остаются брендом Anor. Нет зависимостей, blur, эффектов и новых таймеров. В настройках — подписанные radio swatches с accessibilityState checked и выбором по нажатию.

Акцент хранится отдельной строкой accent в существующих anor_preferences, через storage adapter и Expo AsyncFunctions readAccent/writeAccent (default blue, allowlist семи имён). Preference записывается async с проверкой commit, JS сериализует записи темы/цвета, показывает ошибку записи и защищает начальную загрузку от перезаписи нового выбора.

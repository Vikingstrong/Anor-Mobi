# Product Requirements — Anor Balance

Статус: проектирование, 2026-11-10. Этот документ описывает планируемое поведение, а не готовые функции.

## Проблема и аудитория

Владельцу SIM Anor неудобно собирать баланс из USSD и остатки из SMS. Нужен один понятный экран последних известных значений. Основной пользователь — автор проекта, знакомый с React/Next.js/TypeScript и изучающий React Native. Вторичная аудитория — несколько друзей, самостоятельно устанавливающих APK. Их телефоны могут отличаться, поэтому успех на одном устройстве не означает поддержку всех.

## Цели и нецели

Цели: быстрый локальный Dashboard, явная свежесть данных, обновление баланса при поддержке Android и Anor, ручной импорт пакетов без SMS permissions, понятный учебный код. Использование без мобильного интернета возможно для cache/импорта и, если работает сеть оператора, USSD. Авиарежим не является рабочим offline-сценарием для USSD.

Не входят: backend, регистрация, общий аккаунт для друзей, платежи, подключение тарифов, iOS, магазин приложений, автоматическое распознавание тарифа, multi-operator framework, гарантированная фоновая автоматизация, управление тарифным периодом по предполагаемой дате установки.

## User stories

- Как владелец SIM, я вижу баланс, пакеты и время их фактического получения.
- Я выбираю ULTRA/LITE и отличаю выбранный мной тариф от подтверждённых оператором остатков.
- Я нажимаю «Обновить баланс» и получаю результат либо понятную ошибку без потери cache.
- Я вставляю SMS, проверяю извлечённые поля и подтверждаю сохранение.
- При отказе в разрешении я продолжаю пользоваться импортом и cache.
- На двух SIM я выбираю нужную подписку; приложение не отправляет запрос по случайной SIM.
- Как друг автора, я устанавливаю APK без настройки сервера и без получения чужих данных.

## Объём MVP

MVP завершён после этапов 1–3 и минимальной release-проверки этапа 5. Этап 1 сам по себе — UI-прототип, а не работающий клиент оператора. Если USSD не работает на целевом телефоне, согласовать сокращённый MVP: dialer + ручной ввод баланса + импорт SMS. Не объявлять такую замену реализованной автоматически.

Функциональные требования:

| ID | Требование |
| --- | --- |
| F1 | Dashboard: название приложения/Anor, настройки, выбранный тариф, плата и период, баланс TJS, четыре пакета, статус обновления |
| F2 | Ручной выбор ULTRA/LITE; подпись «Выбран вручную», дата окончания отдельно от длительности тарифа |
| F3 | Кнопка баланса запускает не более одного `*100#`; успешный callback ещё требует успешного разбора суммы |
| F4 | Кнопка пакетов в MVP открывает импорт SMS; не подразумевает неизвестную команду оператора |
| F5 | Импорт: вставка → parse → preview → подтверждение → сохранение; незнакомый/неоднозначный текст ничего не портит |
| F6 | Refresh All при подтверждённом сценарии выполняет один USSD и предлагает импорт для недостающих пакетов; до проверки скрыт/недоступен с объяснением |
| F7 | SIM settings, импорт, тариф, «О приложении», очистка локальных данных; неофициальность указана явно |
| F8 | Последние известные значения и настройки сохраняются; cold start без сети показывает их с исходными timestamp |
| F9 | Ошибка одного источника не стирает данные другого; частичные обновления меняют только распознанные поля |
| F10 | Смена SIM/подтверждённая замена подписки очищает текущий набор значений; не смешивать счета |

Часы ночного интервала и актуальность условий для конкретной SIM не установлены. Коды подключения тарифов не входят в функциональность.

## UI и состояния

По уточнению владельца: минимализм в духе Apple, светлая нейтральная тема, небольшой гранатовый акцент, крупная сумма и простые карточки. Без градиентов, blur, тяжёлых анимаций и декоративных графиков. Системный шрифт и native-компоненты; приоритет — отзывчивость на A12/Helio P35. Без копирования логотипа оператора. Русский интерфейс, понятные подписи, достаточный контраст, touch targets от 48 dp, поддержка увеличенного системного шрифта и TalkBack. Дневной/ночной пакеты различаются текстом, не только цветом.

- Empty: «Нет данных», действия для получения. Mock только в явно обозначенном demo-режиме.
- Loading: индикатор у операции, прежние значения остаются видимыми; повторная отправка заблокирована.
- Success: обновляются только полученные поля и их timestamps.
- Error: причина и действие (разрешение, SIM, сеть, ручной режим); cache остаётся.
- Partial: баланс получен, пакеты ещё не импортированы; не показывать общий успех всех показателей.
- Stale: видимое время получения и «Данные могли измениться»; локальный порог 24 часа — только UX-эвристика, не обещание точности.

Процент = остаток / сопоставимый лимит × 100. При неизвестном остатке/лимите полосы и процента нет. При превышении лимита число не обрезается, полоса ограничивается 100%, есть пояснение о возможных бонусах/несовпадении тарифа. После смены выбранного тарифа старые остатки остаются с предупреждением; сравнение с новым лимитом отключено до нового подтверждения импорта/обновления. Дата окончания — только из подтверждённого источника, иначе «Неизвестна».

Общий Last Updated означает последнее успешное получение хотя бы одного поля; у баланса и пакетов отдельное время. Последняя попытка и время локальной записи не подменяют время получения операторских данных.

## Нефункциональные требования

Нет запросов на серверы приложения, внешних шрифтов, рекламы и аналитики. Все основные действия работают без IP-интернета, кроме самой загрузки инструментов разработки. Release APK не зависит от Metro. Неподдерживаемый native API не вызывает crash. Цель cold start — до 2 секунд на телефоне владельца, измерить на release после получения модели; это целевой показатель, не текущий результат. Операции имеют конечное ожидание, приложение остаётся отзывчивым. Формат storage версионирован, повреждённый cache восстанавливается безопасно.

## Приёмка

1. Чистая установка не показывает выдуманные нули или заполненные пакеты.
2. Разрешённый USSD на проверенном устройстве показывает сумму, совпадающую с ответом; ошибка/timeout сохраняет старые данные.
3. Подтверждённые реальные SMS разбираются с правильными единицами; неизвестные не изменяют cache.
4. После перезапуска без интернета сохраняются значения, источник, время; исходный SMS не хранится.
5. Отказ/отзыв permissions не блокирует ручной режим.
6. Проверены нужная SIM, смена SIM и повторное нажатие; поздний ответ не попадает в другой контекст.
7. Подписанный APK запускается без dev server; нет лишних permissions, передачи пользовательских данных и чувствительных логов.

Зависимости проверки: телефон с Anor и реальные образцы. До этого пункты 2, 3, 6 не считаются выполненными.

## Уточнения владельца после просмотра на A12, 2026-11-11

- Первая светлая версия признана слишком скучной. Нужны выразительная типографика, аккуратные карточки и заполненные полосы вместе с числами, без декоративного шума, blur и тяжёлых анимаций.
- Тема по умолчанию системная; доступны ручные светлая и тёмная темы. Изменение системной темы должно менять оформление приложения.
- Максимум — маленьким шрифтом справа под полосой (`макс. 30 000 МБ`); процент остатка слева. Неизвестные значения не отображаются как 0%.
- Под каждым показателем пакета видно собственное время последнего успешного обновления; баланс имеет отдельное время. Нажатие кнопки и открытие dialer не обновляют timestamps.
- Владелец подтвердил: ответ баланса приходит практически сразу; тариф и пакеты приходят от **AnorINFO** отдельным SMS, иногда через несколько минут.
- Основная кнопка проверки и круговая стрелка запускают один подтверждённый `*100#`, без выдуманной отдельной команды пакетов. В ручном режиме интерфейс прямо сообщает, что нужно нажать вызов в системном приложении и что значения автоматически не прочитаются.
- Нужны раздельные состояния «отправляем запрос», «ожидаем USSD», «баланс получен», «ожидаем SMS», «SMS получено», «пакеты обновлены», ошибки и истечение ожидания. Ответ без успешно разобранных полей ещё не равен обновлению данных.
- Во время ожидания SMS показывать прошедшее время и сохранять прежние значения/их время. Не держать USSD loader несколько минут и не посылать автоматически повторные запросы. Дедлайн USSD не является дедлайном SMS.

Текущая UI-реализация: обе темы, настройки System/Light/Dark, карточки с полосами/максимумом/временем, явный opt-in пример с синтетическими числами, ручной запуск dialer. Автоматические USSD/SMS события ещё не реализованы. UI не показывает фиктивный успех получения операторских данных. Настройки и пример пока в памяти, не сохраняются между полными перезапусками.

## Актуальная логика по последнему уточнению владельца, 2026-11-11

Этот раздел заменяет прежние предположения о единственной команде и manual-only обновлении. *100# — только денежный баланс. *104# — тариф/пакеты, сообщение AnorINFO может прийти через несколько минут. Кнопка баланса выполняет только 100, кнопка пакетов — только 104, «Проверить всё» — обе последовательно без параллельных modem sessions. Открытие приложения «Телефон» из refresh удалено. Выбор SIM явный, для телефона владельца — Anor в слоте 2.

SMS automation добровольная: RECEIVE_SMS, только при открытом приложении, без истории сообщений. При отказе/невозможности разрешения — вставка → preview → подтверждение. Последний успешный баланс/остатки сохраняются при ошибках. Каждый показатель получает собственный timestamp только после успешного разбора. Импорт показывает время импорта, не предполагаемое время отправки SMS.

Максимум справа под полосой — просто значение и единица (30000 МБ, 1000 мин, 50 SMS), без «макс.». Минуты и SMS — отдельные полноширинные карточки, ниже по высоте интернет-карточек. Для исходного интернет-поля SMS используется нейтральное название «Интернет»: операторское поле не содержит слова «дневной».

Реализация подготовлена, реальное получение через API ещё требует проверки на новом APK. Из корпуса подтверждён один ULTRA SMS, автоматическое сопоставление названия тарифа реализовано для него; дополнительные варианты LITE не объявляются проверенными.

## Расход и прогноз — поручение 2026-11-11

Отдельный спокойный блок «Расход и прогноз», переключение Интернет/Ночной. Расход за последние 24 часа и 7 дней сопровождается реальной длительностью и датами наблюдений. Пропуски не равны нулевому расходу. Новый пакет/видимое пополнение начинают новый расчёт. Прогноз после >=3 проверок за >=сутки, по свежим данным за неделю и сроку пакета: средние МБ/сутки, ожидаемый остаток к окончанию или дата исчерпания. При недостатке/старении данных понятное объяснение и обычная проверка пакетов, без автоматических USSD. Demo не выдаёт синтетический прогноз за пользовательский.

## Исправления по наблюдению владельца — 2026-11-12

Рост МБ из-за корректировок оператора больше не сбрасывает расход/прогноз. Возврат после роста до прежнего остатка не считается повторным расходом; реальное последнее значение отображается как получено. Новый срок/тариф по-прежнему начинают новый расчёт. Пример: 1000→800→1200→800→700 означает 300 МБ наблюдаемого расхода.

SIM автоматически: Anor по имени оператора, иначе SIM для звонков по умолчанию. Ручной режим остаётся в настройках; при невозможности определить default для нескольких SIM нужен явный выбор. Коды всё ещё отправляются только кнопкой пользователя. При автоопределении той же SIM накопленные данные сохраняются. Режим и выбранный слот видны на экране; никакого скрытого USSD при запуске.

2026-11-12: выбор акцентного цвета в настройках — синий (текущий default), зелёный, оранжевый, красный, фиолетовый, бирюзовый, розовый. Цвет сохраняется после перезапуска и адаптируется к light/dark/system; меняет кнопки/полосы/выделения, не подменяет показания. Настройки открываются шестерёнкой вместо трёх точек. По прямому поручению владельца после реализации собрать/установить обновление и сохранить готовый APK в Download телефона.

2026-11-12, 0.4: шесть основных тарифов официального каталога, selector auto/manual, поля по тарифу, отдельный последний снимок каждого тарифа без потери при ручном возврате. Архивные данные помечаются и не выдаются за актуальное состояние SIM; минуты/интернет/SMS не придумываются из каталога. У 15 мегабайты скрыты на основном экране, но старые snapshots видны в истории. Настройки открываются/закрываются короткой анимацией, системный Reduce Motion соблюдается. Владелец разрешил сборку, установку, Download APK и commit/push исходников в GitHub.

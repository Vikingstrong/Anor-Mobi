# Product Requirements — Anor Balance

Статус: проектирование, 2026-11-10. Этот документ описывает планируемое поведение, а не готовые функции.

## Проблема и аудитория

Владельцу SIM Anor неудобно собирать баланс из USSD и остатки из SMS. Нужен один понятный экран последних известных значений. Основной пользователь — автор проекта, знакомый с React/Next.js/TypeScript и изучающий React Native. Вторичная аудитория — несколько друзей, самостоятельно устанавливающих APK. Их телефоны могут отличаться, поэтому успех на одном устройстве не означает поддержку всех.

## Цели и нецели

Цели: быстрый локальный Dashboard, явная свежесть данных, обновление баланса при поддержке Android и Anor, ручной импорт пакетов без SMS permissions, понятный учебный код. Использование без мобильного интернета возможно для cache/импорта и, если работает сеть оператора, USSD. Авиарежим не является рабочим offline-сценарием для USSD.

Не входят: backend, регистрация, общий аккаунт для друзей, платежи, подключение тарифов, iOS, магазин приложений, автоматическое распознавание тарифа, multi-operator framework, гарантированная фоновая автоматизация, управление тарифным периодом по предполагаемой дате установки.

## User stories

- Как владелец SIM, я вижу баланс, пакеты и время их фактического получения.
- Я выбираю ULTRA/LITE и отличаю выбранный мной тариф от подтверждённых оператором остатков.
- Я нажимаю «Обновить баланс» и получаю результат либо понятную ошибку без потери cache.
- Я вставляю SMS, проверяю извлечённые поля и подтверждаю сохранение.
- При отказе в разрешении я продолжаю пользоваться импортом и cache.
- На двух SIM я выбираю нужную подписку; приложение не отправляет запрос по случайной SIM.
- Как друг автора, я устанавливаю APK без настройки сервера и без получения чужих данных.

## Объём MVP

MVP завершён после этапов 1–3 и минимальной release-проверки этапа 5. Этап 1 сам по себе — UI-прототип, а не работающий клиент оператора. Если USSD не работает на целевом телефоне, согласовать сокращённый MVP: dialer + ручной ввод баланса + импорт SMS. Не объявлять такую замену реализованной автоматически.

Функциональные требования:

| ID | Требование |
| --- | --- |
| F1 | Dashboard: название приложения/Anor, настройки, выбранный тариф, плата и период, баланс TJS, четыре пакета, статус обновления |
| F2 | Ручной выбор ULTRA/LITE; подпись «Выбран вручную», дата окончания отдельно от длительности тарифа |
| F3 | Кнопка баланса запускает не более одного `*100#`; успешный callback ещё требует успешного разбора суммы |
| F4 | Кнопка пакетов в MVP открывает импорт SMS; не подразумевает неизвестную команду оператора |
| F5 | Импорт: вставка → parse → preview → подтверждение → сохранение; незнакомый/неоднозначный текст ничего не портит |
| F6 | Refresh All при подтверждённом сценарии выполняет один USSD и предлагает импорт для недостающих пакетов; до проверки скрыт/недоступен с объяснением |
| F7 | SIM settings, импорт, тариф, «О приложении», очистка локальных данных; неофициальность указана явно |
| F8 | Последние известные значения и настройки сохраняются; cold start без сети показывает их с исходными timestamp |
| F9 | Ошибка одного источника не стирает данные другого; частичные обновления меняют только распознанные поля |
| F10 | Смена SIM/подтверждённая замена подписки очищает текущий набор значений; не смешивать счета |

Оба также включают безлимит внутри Anor. Это не часть ограниченного счётчика минут. Храним официальные МБ; обозначения ГБ и коэффициент пересчёта остаются предметом проверки. Часы ночного интервала и актуальность условий для конкретной SIM не установлены. Коды подключения тарифов не входят в функциональность.

## UI и состояния

Светлая нейтральная тема, спокойный гранатовый акцент, крупная сумма, округлые карточки; без копирования логотипа оператора. Русский интерфейс, понятные подписи, достаточный контраст, touch targets от 48 dp, поддержка увеличенного системного шрифта и TalkBack. Дневной/ночной пакеты различаются текстом, не только цветом.

- Empty: «Нет данных», действия для получения. Mock только в явно обозначенном demo-режиме.
- Loading: индикатор у операции, прежние значения остаются видимыми; повторная отправка заблокирована.
- Success: обновляются только полученные поля и их timestamps.
- Error: причина и действие (разрешение, SIM, сеть, ручной режим); cache остаётся.
- Partial: баланс получен, пакеты ещё не импортированы; не показывать общий успех всех показателей.
- Stale: видимое время получения и «Данные могли измениться»; локальный порог 24 часа — только UX-эвристика, не обещание точности.

Процент = остаток / сопоставимый лимит × 100. При неизвестном остатке/лимите полосы и процента нет. При превышении лимита число не обрезается, полоса ограничивается 100%, есть пояснение о возможных бонусах/несовпадении тарифа. После смены выбранного тарифа старые остатки остаются с предупреждением; сравнение с новым лимитом отключено до нового подтверждения импорта/обновления. Дата окончания — только из подтверждённого источника, иначе «Неизвестна».

Общий Last Updated означает последнее успешное получение хотя бы одного поля; у баланса и пакетов отдельное время. Последняя попытка и время локальной записи не подменяют время получения операторских данных.

## Нефункциональные требования

Нет запросов на серверы приложения, внешних шрифтов, рекламы и аналитики. Все основные действия работают без IP-интернета, кроме самой загрузки инструментов разработки. Release APK не зависит от Metro. Неподдерживаемый native API не вызывает crash. Цель cold start — до 2 секунд на телефоне владельца, измерить на release после получения модели; это целевой показатель, не текущий результат. Операции имеют конечное ожидание, приложение остаётся отзывчивым. Формат storage версионирован, повреждённый cache восстанавливается безопасно.

## Приёмка

1. Чистая установка не показывает выдуманные нули или заполненные пакеты.
2. Разрешённый USSD на проверенном устройстве показывает сумму, совпадающую с ответом; ошибка/timeout сохраняет старые данные.
3. Подтверждённые реальные SMS разбираются с правильными единицами; неизвестные не изменяют cache.
4. После перезапуска без интернета сохраняются значения, источник, время; исходный SMS не хранится.
5. Отказ/отзыв permissions не блокирует ручной режим.
6. Проверены нужная SIM, смена SIM и повторное нажатие; поздний ответ не попадает в другой контекст.
7. Подписанный APK запускается без dev server; нет лишних permissions, передачи пользовательских данных и чувствительных логов.

Зависимости проверки: телефон с Anor и реальные образцы. До этого пункты 2, 3, 6 не считаются выполненными.

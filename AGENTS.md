## Продукт и стек

Личный Android-проект, возможна установка APK друзьям. Нет сервера, авторизации, аналитики, облачной синхронизации. Предложены React Native, strict TypeScript, Expo Development Build/Prebuild, Kotlin через локальный Expo Module, Zustand, AsyncStorage, StyleSheet, Jest. Исходный шаблон: Expo SDK 58 / React Native 0.88.1 / React 19.3.0 / TypeScript 6.0.3, Node 24 LTS. Точные зависимости фиксируются package-lock.json. Не добавлять зависимости без объяснения назначения и более простых альтернатив.

Объяснять сложные решения на русском. Для Kotlin пояснять границу JS/native, поток callback, lifecycle и permissions. Предлагать небольшое учебное упражнение, не блокируя им работу.

## Архитектура и код

- UI → application services → adapters; UI не вызывает TelephonyManager и не парсит SMS.
- Чистые парсеры и типы не зависят от React, Android, Zustand и хранилища.
- Статический тариф отделён от фактических остатков. Неизвестное ≠ ноль. Нет выдуманных форматов и рабочих USSD-команд.
- TypeScript: strict, без `any` и необоснованных `!`/type assertions; внешние данные сначала `unknown`, затем runtime validation. Discriminated unions для результатов, exhaustive handling. Имена компонентов PascalCase, функций camelCase.
- Kotlin: null safety без `!!`, узкая обработка ожидаемых исключений, отсутствие блокировки UI thread. Promise завершается ровно один раз; timeout и поздний callback не меняют завершённую операцию.
- На мосте только JSON-совместимые значения; даты — строки, ошибки — коды, без Android-объектов и throwable. Контракт описан в DATA_MODELS.
- Кастомный native-код держать в `modules/`, настройки — в config/plugin. Не править сгенерированный `android/` вручную без ADR о смене workflow.
- Хранение версионировать, ошибки записи не выдавать за сохранённые данные. Не сохранять transient loading, permission grants и исходные SMS.

## Безопасность и проверка

Permissions запрашиваются по действию пользователя с объяснением; отказ сохраняет ручной режим. Никаких USSD при запуске или в фоне в MVP. Только allowlist `*100#` (баланс) и `*104#` (тариф/пакеты), обе команды подтверждены владельцем; dialer fallback также требует действия пользователя. Не добавлять Accessibility, root и private telephony API.

Для бизнес-логики нужны содержательные Jest-тесты: разбор подтверждённых форматов, неизвестные поля, частичное обновление, единицы, даты, конкуренция и ошибки storage. Для Kotlin — проверки состояния операции и ручная матрица на реальном телефоне; эмулятор и mock не подтверждают USSD оператора. Для простых правок документации/UI не писать тесты ради количества. Не утверждать, что тест выполнен, если он только запланирован.

SMS и USSD не логировать целиком. Реальные fixtures только после обезличивания; mock помечать и отделять от пользовательского cache. Не коммитить номера, SMS, keystore, пароли и локальные настройки SDK.

## Документация и Git

Изменение границ модулей, permissions, storage или контрактов сопровождается правкой соответствующего документа и ADR. Проверяемые внешние факты снабжать официальным источником и датой, наблюдения устройства — моделью/версией и результатом. Неподтверждённое явно маркировать.

Перед изменениями проверять status/diff, сохранять чужую работу. Маленькие предметные коммиты только по заданию/принятому workflow. Не делать push, force push, reset, массовое удаление или публикацию APK без соответствующего поручения. Git и origin уже подключены владельцем; не изменять remote и не отправлять коммиты без поручения.

## Дизайн и производительность

По уточнению владельца: минимализм в духе Apple, без шаблонного AI-декора; A12/Helio P35 — целевое устройство. Стандартные native-компоненты, системный шрифт, StyleSheet, спокойные цвета и свободные отступы. Без blur, градиентов, декоративных графиков, тяжёлых анимаций и UI kits. Реальную плавность измерять на телефоне, не обещать её по одному виду кода.

После зависания ноутбука 2026-11-10 не запускать тяжёлую сборку автоматически. Для следующей явно согласованной попытки использовать только `npm run build:android` с systemd-лимитами; не обходить wrapper прямым gradlew/expo run:android. Не запускать параллельно Metro/export/другую компиляцию. При недостатке памяти завершить с понятной ошибкой, не увеличивать лимиты самовольно.

Уточнения UI 2026-11-11: default system theme, ручные light/dark, числа + полосы, максимум справа мелким шрифтом (МБ), timestamp под каждым показателем. Баланс отвечает быстро, SMS тарифов/пакетов от AnorINFO может задержаться на несколько минут. Состояния получения каналов раздельны; не показывать фиктивное ожидание/получение SMS при отсутствии SMS source и не обновлять timestamps от одного нажатия. Demo всегда явно помечен и отделён от SIM, ручной dialer не выдаётся за sendUssdRequest.

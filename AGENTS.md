# Работа над Anor Balance

## Текущий этап

Создана документация. Не создавать приложение, UI, native-модули и не устанавливать зависимости до разрешения владельца на реализацию. Явное последующее задание владельца определяет разрешённый этап. Не трактовать roadmap как разрешение выполнить всё сразу.

## Продукт и стек

Личный Android-проект, возможна установка APK друзьям. Нет сервера, авторизации, аналитики, облачной синхронизации. Предложены React Native, strict TypeScript, Expo Development Build/Prebuild, Kotlin через локальный Expo Module, Zustand, AsyncStorage, StyleSheet, Jest. Версии ещё не выбраны; зафиксировать совместимость перед инициализацией. Не добавлять зависимости без объяснения назначения и более простых альтернатив.

## Рабочий цикл

1. Прочитать связанные документы и существующий код; обозначить небольшой проверяемый результат.
2. Сделать минимальное изменение в рамках задания, не смешивать UI, интеграции и рефакторинг.
3. Проверить поведение подходящим способом; сообщить выполненные проверки и ограничения.
4. Обновить затронутую документацию; переходить к следующей итерации по согласованному объёму работы.

Объяснять сложные решения на русском. Для Kotlin пояснять границу JS/native, поток callback, lifecycle и permissions. Предлагать небольшое учебное упражнение, не блокируя им работу.

## Архитектура и код

- UI → application services → adapters; UI не вызывает TelephonyManager и не парсит SMS.
- Чистые парсеры и типы не зависят от React, Android, Zustand и хранилища.
- Статический тариф отделён от фактических остатков. Неизвестное ≠ ноль. Нет выдуманных форматов и рабочих USSD-команд.
- TypeScript: strict, без `any` и необоснованных `!`/type assertions; внешние данные сначала `unknown`, затем runtime validation. Discriminated unions для результатов, exhaustive handling. Имена компонентов PascalCase, функций camelCase.
- Kotlin: null safety без `!!`, узкая обработка ожидаемых исключений, отсутствие блокировки UI thread. Promise завершается ровно один раз; timeout и поздний callback не меняют завершённую операцию.
- На мосте только JSON-совместимые значения; даты — строки, ошибки — коды, без Android-объектов и throwable. Контракт описан в DATA_MODELS.
- Кастомный native-код держать в `modules/`, настройки — в config/plugin. Не править сгенерированный `android/` вручную без ADR о смене workflow.
- Хранение версионировать, ошибки записи не выдавать за сохранённые данные. Не сохранять transient loading, permission grants и исходные SMS.

## Безопасность и проверка

Permissions запрашиваются по действию пользователя с объяснением; отказ сохраняет ручной режим. Никаких USSD при запуске или в фоне в MVP. Только allowlist `*100#`; dialer fallback также требует действия пользователя. Не добавлять Accessibility, root и private telephony API.

Для бизнес-логики нужны содержательные Jest-тесты: разбор подтверждённых форматов, неизвестные поля, частичное обновление, единицы, даты, конкуренция и ошибки storage. Для Kotlin — проверки состояния операции и ручная матрица на реальном телефоне; эмулятор и mock не подтверждают USSD оператора. Для простых правок документации/UI не писать тесты ради количества. Не утверждать, что тест выполнен, если он только запланирован.

SMS и USSD не логировать целиком. Реальные fixtures только после обезличивания; mock помечать и отделять от пользовательского cache. Не коммитить номера, SMS, keystore, пароли и локальные настройки SDK.

## Документация и Git

Изменение границ модулей, permissions, storage или контрактов сопровождается правкой соответствующего документа и ADR. Проверяемые внешние факты снабжать официальным источником и датой, наблюдения устройства — моделью/версией и результатом. Неподтверждённое явно маркировать.

Перед изменениями проверять status/diff, сохранять чужую работу. Маленькие предметные коммиты только по заданию/принятому workflow. Не делать push, force push, reset, массовое удаление или публикацию APK без соответствующего поручения. Сейчас Git не инициализирован; служебный `.git` среды не исправлять и не удалять.
